# 肿瘤科智能检测门诊系统 — 接口文档 V1.0

> 基于《肿瘤科智能检测门诊系统-业务功能文档(学生开发版)》输出。
>
> 目标：给前端、后端、测试提供一份统一的 **最新接口契约**。
>
> 本文档按功能模块划分：**认证、患者预约、患者AI诊断、患者病历处方、医生接诊、医生病历处方、医生AI图文诊断、医生药品库存、管理员用户管理、管理员数据监控**。

---

## 1. 通用约定

### 1.1 Base URL

- **本地开发**：`http://127.0.0.1:8000`
- 线上环境按网关或部署域名调整。

### 1.2 鉴权方式

采用 **Laravel Sanctum / Session** 鉴权。

- 公开接口：`/api/auth/register`、`/api/auth/login` 不需要登录
- 患者端 `/api/patient/*` — 需登录，角色 `patient`
- 医生端 `/api/doctor/*` — 需登录，角色 `doctor`
- 管理员端 `/api/admin/*` — 需登录，角色 `admin`

### 1.3 统一响应格式

所有接口统一返回：

```json
{
  "code": 0,
  "msg": "成功",
  "data": {},
  "success": true,
  "trace_id": "8f45a7d5-d8b2-4d7a-b6e3-123456789abc"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | number | 业务状态码，成功为 `0`（详见附录响应码表） |
| msg | string | 业务提示信息 |
| data | mixed | 返回数据，可能为对象、数组或 `null` |
| success | boolean | 是否成功 |
| trace_id | string | 链路追踪 ID，便于排查问题 |

### 1.4 分页响应格式

分页接口的 `data` 统一为：

```json
{
  "list": [],
  "page": 1,
  "size": 10,
  "total": 100,
  "total_pages": 10
}
```

### 1.5 时间与排序约定

- 时间字段统一使用 ISO 8601，例如：`2026-07-26T14:30:00`
- 分页参数：`page` 从 `1` 开始，`size` 默认 `10`
- 排序参数示例：`sort=created_at:desc`

### 1.6 请求参数示例写法

本文档中的"请求参数示例"统一采用如下结构：

- `path`：路径参数
- `query`：查询参数
- `body`：JSON 请求体
- `formData`：`multipart/form-data` 表单字段

无对应参数时，会明确写为 `null` 或空对象 `{}`。

### 1.7 通用枚举约定

#### 1.7.1 用户角色

| 枚举值 | 说明 |
| --- | --- |
| `patient` | 患者 |
| `doctor` | 肿瘤科医生 |
| `admin` | 管理员 |

#### 1.7.2 预约状态

| 枚举值 | 说明 |
| --- | --- |
| `pending` | 待接诊 |
| `called` | 已叫号 |
| `in_progress` | 接诊中 |
| `completed` | 已完成 |
| `cancelled` | 已取消 |

#### 1.7.3 处方状态

| 枚举值 | 说明 |
| --- | --- |
| `pending` | 待取药 |
| `dispensed` | 已取药 |

#### 1.7.4 AI 诊断类型

| 枚举值 | 说明 |
| --- | --- |
| `text` | 文字诊断（患者端） |
| `image` | 图文诊断（医生端） |

#### 1.7.5 库存变动类型

| 枚举值 | 说明 |
| --- | --- |
| `in` | 入库 |
| `out` | 出库（患者取药自动扣减） |

#### 1.7.6 账号状态

| 枚举值 | 说明 |
| --- | --- |
| `active` | 正常 |
| `disabled` | 已禁用 |

### 2.2 `POST /api/auth/register`

- **接口中文名**：患者注册
- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 姓名，2-50字符，支持中文 |
| email | string | 是 | 邮箱地址 |
| password | string | 是 | 密码，6-100字符 |
| password_confirmation | string | 是 | 确认密码，须与 password 一致 |
| phone | string | 否 | 手机号码，11位 |

- **请求参数示例**

```json
{
  "body": {
    "name": "张三",
    "email": "zhangsan@example.com",
    "password": "password123",
    "password_confirmation": "password123",
    "phone": "13800138000"
  }
}
```

- **响应 `data`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | number | 用户 ID |
| name | string | 姓名 |
| email | string | 邮箱 |
| role | string | 角色，固定为 `patient` |
| created_at | string | 注册时间 |

```json
{
  "data": {
    "id": 3,
    "name": "张三",
    "email": "zhangsan@example.com",
    "role": "patient",
    "created_at": "2026-07-26T14:30:00"
  }
}
```

- **错误码**

| code | msg | 条件 |
| --- | --- | --- |
| 10001 | 参数错误 | 必填字段缺失或格式不正确 |
| 10002 | 必填参数缺失 | name/email/password 任一为空 |
| 10003 | 参数格式错误 | 邮箱格式不正确或密码长度不足 |
| 30003 | 邮箱已被注册 | 该邮箱已存在 |

**业务规则**：仅患者可自助注册；注册后角色固定为 `patient`；医生和管理员账号由后台创建。

### 9.7 库存业务规则总结

| 规则 | 说明 |
| --- | --- |
| 自动扣减 | 患者确认取药 → 系统自动扣减库存，生成 `type=out` 记录 |
| 库存校验 | 开具处方时校验库存（不足则拒绝开具）；取药时二次校验（不足则拒绝取药，事务回滚） |
| 异常提示 | 库存不足时返回 `40004`，前端提示"库存不足" |
| 全程追溯 | 每次库存变动记录前后数量和关联业务，支持按药品/类型/日期查询 |
| 禁止手动出库 | 出库仅系统自动触发，不提供手动出库接口 |

## 12. DTO 定义汇总

> 以下为各模块接口的请求体（Request）数据结构定义。

### 12.1 认证模块

#### `RegisterRequest` — 患者注册

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 姓名，2-50字符，支持中文 |
| email | string | 是 | 邮箱地址 |
| password | string | 是 | 密码，6-100字符 |
| password_confirmation | string | 是 | 确认密码 |
| phone | string | 否 | 手机号码，11位 |

#### `LoginRequest` — 用户登录

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| email | string | 是 | 邮箱地址 |
| password | string | 是 | 密码 |
| remember | boolean | 否 | 是否记住登录，默认 `false` |

#### `ChangePasswordRequest` — 修改密码

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| current_password | string | 是 | 当前密码 |
